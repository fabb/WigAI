# Story 9.6: Live End-to-End Test

**Epic:** [Epic 9: Project Editing](../prd/epic-9.md)

**User Story:**

*   As a developer, I want a script that exercises the editing tools against a running Bitwig over MCP, so that behaviour the unit tests cannot see (asynchronous updates, values Bitwig silently ignores) is verified before release.

**Acceptance Criteria:**

*   `scripts/live_test.py` (Python 3 standard library only) connects to the MCP endpoint (`--url`, default `http://localhost:61169/mcp`), performs the MCP handshake, and calls tools over the streamable HTTP transport.
*   It refuses to run (exit code 2) unless the open project has at most 2 regular tracks; `--force` overrides. The script creates, edits and deletes tracks and devices and must never be pointed at a real song.
*   It creates its own instrument and audio tracks and checks: track naming, `volume_db`, pan, mute, color; device insert/position/bypass/copy/move/delete; reading all parameter pages and setting parameters by name and by page+index; clip create/write notes/delete; MIDI file import; action listing; metronome toggle (restored afterwards).
*   It deletes its tracks at the end (unless `--keep`) and checks that the regular track count is back to where it started.
*   It prints one line per check and exits non-zero if any check fails.
