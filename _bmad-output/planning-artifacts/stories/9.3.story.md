# Story 9.3: Parameters of Any Device

**Epic:** [Epic 9: Project Editing](../prd/epic-9.md)

**User Story:**

*   As an AI agent, I want to read and set the parameters of any device on any track, across all of its remote-control pages, without changing what the user has selected, so I can configure a chain while the user keeps working.

**Acceptance Criteria:**

*   MCP tools `get_device_parameters` and `set_device_parameters` are implemented and registered.
*   Both identify the device by track (`track_index`/`track_name`) and `device_index`.
*   `get_device_parameters` returns `page_names` and, for every page (or only `page` if given), the existing controls with `index`, `name`, normalized `value` and `display`.
*   `set_device_parameters` takes a non-empty `parameters` array. Each item has `value` (0–1, required) and either:
    *   `name`: matched case-insensitively, searched across all pages; or
    *   `page` + `index`.
*   Each item gets its own result: on success `status`, `page`, `name`, `value`, `display` and `applied` (whether Bitwig reported the new value); on failure `status: "error"` and a `message` ("Parameter not found", "value must be 0.0-1.0"). One failing item does not stop the others.
*   Neither tool changes the user's selected track, device or remote-control page.
*   `api-reference.md` documents both tools.
*   Unit tests cover argument mapping (name vs. page+index, required `value`).

### Implementation Notes

*   A dedicated `CursorTrack` (`createCursorTrack(id, name, 0, 0, false)`) and `PinnableCursorDevice` with a `CursorRemoteControlsPage` of 8 are created at init. The tools point them at the target with `selectChannel` / `selectDevice`, wait until the cursor reports the expected track name, device position and device name, then switch pages via `selectedPageIndex()`.
*   **Bitwig ignores `value().set()` on these remote controls** (it is accepted but never applied; reading works). `value().setImmediately()` applies. This was isolated by trying `set()` on the control thread (`host.scheduleTask`), `set()` on the request thread, and `setImmediately()` in sequence; only the last changed the value.
*   This removes the limitation noted in Story 8.2 that remote controls of non-selected devices are not accessible.
