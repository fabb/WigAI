# Story 9.1: Track Creation and Mixer Tools

**Epic:** [Epic 9: Project Editing](../prd/epic-9.md)

**User Story:**

*   As an AI agent, I want to create, delete and duplicate tracks and set their mixer state (name, volume in dB, pan, mute, solo, arm, activation, monitor mode, color, sends), so I can lay out a project for the user.

**Acceptance Criteria:**

*   MCP tools `create_track`, `delete_track`, `duplicate_track`, `get_track_mixer`, `set_track` and `set_send` are implemented and registered.
*   `create_track` accepts `type` (`audio` | `instrument` | `effect`, required), `position` (optional) and `name` (optional). It returns the new track's `track_index` and `name`.
    *   For audio and instrument tracks `position` is an index among regular tracks; for effect tracks it is an index among effect tracks. Default is the end of that group.
    *   The tool waits until the track count of that group increases, then verifies that the track at the expected index exists, is not the master track, and has the requested type before applying `name`. If any check fails it returns an error and renames nothing.
*   `delete_track` and `duplicate_track` refuse the master track with `INVALID_PARAMETER`.
*   `set_track` changes only the fields that are given:
    *   `name`, `mute`, `solo`, `arm`, `activated`, `monitor_mode` (`ON` | `OFF` | `AUTO`), `color` (`#RRGGBB`).
    *   `volume`: raw normalized fader position 0–1.
    *   `volume_db`: target in dB. Because the fader curve is not exposed, the tool binary-searches the normalized value against Bitwig's displayed dB and keeps the position whose display was closest to the target (the display is rounded to 0.1 dB).
    *   `pan`: −1 (left) to 1 (right), mapped to the normalized 0–1 value.
*   `get_track_mixer`, `set_track` and `set_send` return the full mixer state including sends (`index`, `name`, `value`, `display`, `enabled`).
*   `set_send` sets a send's `value` (0–1) and/or `enabled`; a missing send returns `INVALID_RANGE`.
*   `api-reference.md` documents all six tools.
*   Unit tests cover track resolution, master-track protection, the regression where a slow-to-appear track caused the master to be renamed, pan/color mapping, and missing send banks.

### Implementation Notes

*   The main track bank is created with 8 sends (previously 0) so sends are reachable; `BitwigApiFacadeTest` is updated accordingly.
*   `Track.sendBank()` throws when the bank has no sends; access is wrapped so mixer reads still succeed.
*   Send properties (`exists`, `name`, `value`, `displayedValue`, `isEnabled`) and `trackType` are marked interested at init.
